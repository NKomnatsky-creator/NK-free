# Безопасность free-сборки

## Что нельзя коммитить

Следующие файлы создаются локально и содержат секреты или данные пользователей:

- `.flask_secret` — секрет подписи сессий. Утечка позволяет подделать сессию администратора.
- `secret.key` — ключ шифрования паролей в `passwords.db`.
- `passwords.db` — база паролей (даже в зашифрованном виде не публикуется).
- `master.json` — зашифрованная копия ключа при включённом мастер-пароле.
- `backups/` — резервные копии базы.
- `.env`, токены и пароли в переменных окружения.

В Docker все эти файлы живут в `/data` и не попадают в образ: контекст сборки
ограничён `.dockerignore`, а данные монтируются томом.

## Секреты в Docker

- задавайте `FLASK_SECRET` и `DEFAULT_ADMIN_PASSWORD` через окружение или
  Docker secrets, а не в `Dockerfile`;
- при включённом мастер-пароле передавайте `MASTER_PASSWORD` и храните его
  отдельно от репозитория;
- не публикуйте том `/data` и не добавляйте его в образ.

## Если секрет уже попал в репозиторий

Считайте его скомпрометированным. Удалите файл из рабочей директории **и из
истории коммитов**, затем сгенерируйте новое значение на развёрнутой системе:

- `.flask_secret` → новый случайный секрет, все сессии станут недействительными;
- `secret.key` → заново зашифровать базу (`master.py` / `kdf.py`);
- пароль администратора → сменить при первом же входе.

## Проверка перед первым коммитом

```bash
# Контроль того, что игнорируется
git check-ignore -v .flask_secret secret.key passwords.db master.json

# Поиск случайных секретов в коде
grep -R "PASSWORD\|SECRET\|TOKEN" --include="*.py" .
```
